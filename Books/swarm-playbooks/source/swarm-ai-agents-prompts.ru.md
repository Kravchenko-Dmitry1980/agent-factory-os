Промты: собери «Рой ИИ-агентов» в своём Claude Code
Это набор готовых промтов, который ты можешь копировать целиком и вставлять в свой Claude Code. Каждый промт = один шаг.
Как пользоваться:
Установи Claude Code и открой пустую папку под проект.
Вставляй промты по порядку — от Промта 0 к Промту 6.
Не переходи к следующему промту, пока текущий шаг не заработал.
Claude всё объясняет простым языком и спрашивает разрешения перед серьёзными действиями — это нормально, соглашайся, читай что он пишет.
ПРОМТ 0 — Установка всего необходимого («скилы» и окружение)
Этот промт готовит компьютер: проверяет и ставит Node.js, PostgreSQL, сам Claude Code, токен доступа, и создаёт каркас проекта. Запускать его в пустой папке, из которой ты открыл Claude Code.
Привет! Я не программист, объясняй каждый шаг простым языком и предупреждай
перед тем, как что-то устанавливать или удалять. Мы будем собирать проект
«Рой ИИ-агентов». Сейчас твоя задача — подготовить мой компьютер и рабочую папку,
чтобы дальше всё ставилось без ошибок.

Сделай по порядку:

1. Определи мою операционную систему (macOS или Windows) и дальше используй
   команды именно под неё.

2. Проверь, что установлено, и поставь чего не хватает (на macOS — через Homebrew,
   на Windows — через winget; если менеджера пакетов нет — сначала помоги его поставить):
   - Node.js версии 20 или новее (проверь: node -v)
   - npm (идёт вместе с Node)
   - PostgreSQL версии 16 (проверь: psql --version). На macOS это
     `brew install postgresql@16` и `brew services start postgresql@16`.
   - git (проверь: git --version)
   Перед каждой установкой коротко скажи, что это за программа и зачем она нужна.

3. Проверь доступ к Claude для агентов. Объясни мне, что нужно один раз выполнить
   в терминале команду `claude setup-token` (это использует мою подписку Claude,
   без оплаты за каждый запрос), и подскажи, как потом вставить полученный токен
   в файл .env (мы создадим его дальше).

4. Создай в текущей папке заготовку проекта (монорепозиторий на npm workspaces):
   - package.json в корне со списком workspaces: ["packages/*", "apps/*"]
     и полем "engines": { "node": ">=20" }, проект приватный (private: true).
   - Папки: apps/, packages/, db/.
   - Файл .gitignore (минимум: node_modules, .env, .next, dist, backups).
   - Файл .env.example с пустыми заготовками настроек:
     DATABASE_URL=postgresql://swarm:swarm@localhost:5432/ai_agent_swarm
     BACKEND_PORT=4000
     NEXT_PUBLIC_BACKEND_URL=http://localhost:4000
     CLAUDE_CODE_OAUTH_TOKEN=
     ANTHROPIC_API_KEY=
     ANTHROPIC_MODEL=claude-sonnet-4-6
     TELEGRAM_BOT_TOKEN=
     TELEGRAM_OWNER_CHAT_ID=
     SWARM_PASSWORD=
   - Скопируй .env.example в .env (рабочий файл с секретами, он в .gitignore).
   - Инициализируй git-репозиторий (git init), но пока ничего не коммить.

5. Создай файл CLAUDE.md — это «памятка проекта», которую ты сам будешь читать
   в начале каждой сессии. Запиши туда коротко: что мы строим (рой из 8 ИИ-агентов
   для ведения соцсетей), что владелец не технарь и нужно объяснять простым языком,
   что комментарии и интерфейс — на русском, стек технологий
   (npm workspaces, Next.js + React + Tailwind для дашборда, Node.js + Express +
   tsx для бэкенда, PostgreSQL, Claude Agent SDK для агентов) и что секреты только
   в .env.

6. В конце выведи короткий чек-лист: что установлено, какие версии, что я должен
   сделать руками (получить токен через claude setup-token и вставить его в .env),
   и скажи, что мы готовы к следующему шагу.

Ничего лишнего пока не устанавливай (никаких баз данных проекта, зависимостей
приложений — это сделаем отдельными шагами). Действуй пошагово и сверяйся со мной.

ПРОМТ 1 — Фундамент: база данных, дашборд, бэкенд и первый агент (Стратег)
Продолжаем проект «Рой ИИ-агентов». Сейчас строим фундамент. Объясняй простыми
словами, показывай, что получилось, и в конце мы должны увидеть рабочий дашборд
в браузере с живым чатом со Стратегом.

Сделай:

1. Общий пакет типов packages/shared (имя пакета @swarm/shared) на TypeScript —
   сюда вынесем общие типы данных (агент, сообщение чата и т.д.).

2. База данных PostgreSQL. Создай папку db/ со скриптами:
   - schema.sql — схема. Пока заведи таблицы: agents (id, slug, name, role,
     system_prompt, status, is_active) и chat_messages (id, agent_id, role,
     content, created_at).
   - seed.sql — данные одного агента: Стратег (slug strategist) с характером-
     промптом (системный промпт описывает его как оркестратора-планировщика,
     общается на русском, дружелюбно).
   - setup.sh — создаёт роль swarm (пароль swarm) и базу ai_agent_swarm в
     локальном PostgreSQL, затем применяет schema.sql и seed.sql. Важно: не
     трогать другие базы на компьютере.
   - seed.sh и reset.sh — обновить данные агентов / пересоздать базу с нуля.
   Добавь в корневой package.json команды: db:setup, db:seed, db:reset.

3. Бэкенд apps/backend (имя @swarm/backend) на Node.js + Express 5 (TypeScript,
   запуск через tsx):
   - src/env.ts — читает настройки из .env.
   - src/db.ts — подключение к PostgreSQL.
   - src/index.ts — запуск сервера на порту из BACKEND_PORT, маршрут проверки
     GET /api/health.
   - src/routes/agents.ts — список агентов и история чата.
   - src/agents/conversational.ts — «движок диалога» поверх Claude Agent SDK
     (@anthropic-ai/claude-agent-sdk): берёт системный промпт агента из базы,
     историю чата, шлёт сообщение в Claude, сохраняет ответ. Доступ к Claude
     через CLAUDE_CODE_OAUTH_TOKEN (или ANTHROPIC_API_KEY как запасной), модель
     из ANTHROPIC_MODEL.
   - Маршрут POST /api/agents/:slug/chat — отправить сообщение агенту и получить
     ответ.

4. Дашборд apps/dashboard (имя @swarm/dashboard) на Next.js 16 + React 19 +
   Tailwind CSS 4 (TypeScript):
   - src/lib/api.ts — общение с бэкендом (адрес из NEXT_PUBLIC_BACKEND_URL).
   - src/components/Sidebar.tsx — боковое меню.
   - Страница / (обзор) и страница чата со Стратегом, где можно переписываться,
     и история сохраняется в базе.

5. В корневой package.json добавь команды запуска: dev (бэкенд и дашборд вместе
   через concurrently), dev:backend, dev:dashboard, а также typecheck (проверка
   типов и бэкенда, и дашборда).

6. Запусти npm install, затем npm run db:setup, объясни мне как вставить токен в
   .env, и запусти npm run dev. Проверь, что http://localhost:4000/api/health
   отвечает и что на http://localhost:3000 открывается дашборд с рабочим чатом
   со Стратегом. В конце прогони npm run typecheck и исправь ошибки, если есть.

Адреса: дашборд — http://localhost:3000, бэкенд — http://localhost:4000,
база — localhost:5432 (ai_agent_swarm, пользователь swarm, пароль swarm).

ПРОМТ 3 — Рой: прогоны, Стратег-оркестратор, проверка Критиком, «На проверке»
Продолжаем «Рой ИИ-агентов». Сейчас свяжем агентов в рой: один цель владельца =
один «прогон роя», где Стратег планирует и раздаёт задачи, исполнители их делают,
Критик проверяет, а Стратег пишет итоговую сводку.

Сделай:

1. База данных. Добавь таблицы (через безопасную миграцию db/migrate.sql, чтобы
   не терять данные, и команду npm run db:migrate):
   - runs — прогоны роя (цель, статус, сводка).
   - tasks — доска задач (агент, описание, статус, результат, вердикт Критика,
     зависимости между задачами, номер круга доработки).
   - events — лента уведомлений для владельца (счётчик в дашборде).
   - activity_log — журнал: кто что сделал по каждому прогону.

2. Бэкенд — система прогона:
   - src/agents/orchestrator.ts — движок прогона: планирование (Стратег
     разбивает цель на задачи) → исполнение → проверка Критиком (до 2 кругов
     автодоработки) → сводка владельцу.
   - src/agents/queue.ts — фоновая очередь: выполняет задачи по одной, не блокируя
     дашборд. Если бэкенд перезапустить посреди прогона — незавершённые задачи
     подхватываются при старте.
   - src/agents/tools.ts — «руки» агентов в прогоне, описанные через zod и
     встроенный MCP-сервер Claude Agent SDK, привязанные к конкретному прогону/задаче.
   - src/journal.ts — журнал работы роя и лента уведомлений.
   - Маршруты src/routes/runs.ts и src/routes/events.ts: запустить прогон, узнать
     статус, список задач, одобрить/отправить на доработку результат.
   По умолчанию исполнителями становятся все активные агенты, кроме strategist и
   critic.

3. Логика статусов прогона: мелкий прогон стартует сразу; крупный встаёт в статус
   «ждёт одобрения плана» (владелец смотрит план и жмёт «Запустить»). Когда все
   задачи отработаны — статус «на твоей проверке».

4. Дашборд:
   - «Прогоны роя» (/runs) — список прогонов и страница одного прогона
     (/runs/[id]) с планом, задачами и прогресс-баром.
   - «На проверке» (/review) — по каждому результату кнопки «Одобрить» и
     «На доработку» (с комментарием).
   - Счётчик уведомлений в боковом меню (из таблицы events).

5. (Необязательно) Telegram-уведомления: src/notify.ts — бот пишет владельцу,
   когда план готов к запуску или прогон закончен. Настройки в .env
   (TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_CHAT_ID). Добавь скрипт, который помогает
   узнать свой chat_id (команда npm run telegram:chat-id).

6. Прогони npm run db:migrate, запусти проект, создай тестовый прогон с какой-нибудь
   целью и проверь весь путь: план → исполнение → проверка Критиком → сводка →
   «На проверке» → одобрение. В конце npm run typecheck.

ПРОМТ 4 — Фабрика контента: профиль проекта, замкнутая петля, бюджет
Продолжаем «Рой ИИ-агентов». Сейчас делаем «фабрику контента»: единый бренд-контекст,
автоматические черновики, контроль расходов и более умную связку.

Сделай:

1. Профиль проекта. Добавь таблицу project_profile (одна строка: бизнес, аудитория,
   продукты, тон, табу, примеры). Сделай src/profile.ts, который перед каждым

   На дашборде — страница «Профиль» для редактирования.

2. Замкнутая петля. Добавь таблицы content_plan (что и когда публикуем по площадкам:

   одобряет задачу-публикацию — результат автоматически становится черновиком и

   (/tasks).

3. Контроль расходов. Добавь в таблицы runs и tasks поля стоимости и токенов;

5. Контроль владельца: редактирование плана (правка/удаление/переназначение задач),

   кнопки «копировать» у результатов.

6. Перед облаком: опциональный пароль на дашборд (переменная SWARM_PASSWORD —
   если пустая, авторизация выключена) и команда npm run db:backup (дамп базы в
   папку backups/, хранит последние 14).

Обнови базу через npm run db:migrate, запусти проект, проверь профиль, бюджет и
автосоздание черновика после одобрения. В конце npm run typecheck.

Обновляй базу через npm run db:migrate по ходу дела, запускай проект и проверяй
