Как собрать своих ИИ-агентов с нуля — пошаговый план
Универсальный гайд для любой задачи, которую ты хочешь автоматизировать. Не важно, что именно: ведение соцсетей, поддержка клиентов, ресёрч рынка, разбор документов, личный ассистент, помощник-программист. Принцип один.
Тебе не нужно быть программистом. Всю работу пишет Claude Code — твоя задача правильно поставить цель и вести его по шагам. Этот файл и есть твой маршрут.
 Как пользоваться гайдом
Читай сверху вниз. Этапы идут по порядку — не перепрыгивай.
На каждом этапе есть  Цель,  Что сделать и  Промт — готовый текст, который копируешь и вставляешь в Claude Code.
В промтах заменяй текст в <угловых скобках> на своё.
После каждого этапа есть  Проверка — не идём дальше, пока не работает.
Не торопись. Лучше 5 маленьких работающих шагов, чем один большой и сломанный.
Главное правило: маленькими шагами. Один шаг = одна понятная функция, которую можно проверить глазами.

ЭТАП 0 — Установка инструментов ​
 Цель: подготовить компьютер, чтобы дальше всё ставилось без ошибок.
 Что сделать (один раз)
Редактор кода — VS Code. Скачай с code.visualstudio.com. Это окно, где ты будешь видеть проект.
Node.js (версия 20+). Скачай с nodejs.org (бери LTS). Это «движок», на котором работает большинство таких проектов.
Claude Code. Это и есть твой ИИ-разработчик. Установка — в терминале:
npm install -g @anthropic-ai/claude-code
​
Расширение для VS Code. Открой VS Code → вкладка Extensions (Ctrl/Cmd+Shift+X) → найди «Claude Code» → Install. Теперь сможешь общаться с агентом прямо в редакторе.
Доступ к Claude. В терминале выполни:Это привяжет твою подписку Claude (без оплаты за каждый запрос). Токен понадобится вставить в проект позже.
claude setup-token
​
 Не знаешь, как открыть терминал? В VS Code: меню Terminal → New Terminal. Все команды выполняй там.
 Промт «Проверь и доустанови всё необходимое»
Создай пустую папку под проект, открой её в VS Code, запусти Claude Code (claude в терминале) и вставь:

перед установкой или удалением чего-либо.

Проверь, что на моём компьютере всё готово для разработки, и доустанови недостающее:
1. Определи мою операционную систему и дальше используй команды под неё.
2. Проверь версии: node -v (нужна 20+), npm -v, git --version. Чего нет —
   помоги поставить (на macOS — через Homebrew, на Windows — через winget).
3. Проверь, что доступ к Claude настроен (подскажи про команду claude setup-token).
4. Кратко объясни, что такое терминал, папка проекта и git — простыми словами.
5. В конце выведи чек-лист: что установлено, какие версии, что я должен сделать руками.

Ничего лишнего пока не ставь — только базовые инструменты разработки.

 Проверка
В терминале команды node -v, git --version показывают версии без ошибок, а команда claude запускает агента.
ЭТАП 1 — Определи свою задачу ​
 Цель: превратить размытое «хочу автоматизировать» в чёткое ТЗ. Это самый важный этап — от него зависит всё остальное.
 Что сделать
Ответь письменно на 7 вопросов (прямо в файле или в чате с Claude):
Какую рутину я повторяю руками? (то, что отнимает время каждую неделю)
Что на входе? (тема, ссылка, файл, сообщение клиента, таблица…)
Что должно получиться на выходе? (готовый пост, ответ клиенту, отчёт, саммари…)
Как часто это нужно? (по запросу / каждый день / по событию)
Где я хочу этим пользоваться? (чат, кнопка на сайте, Telegram, таблица…)
Что считается «хорошо сделано»? (критерии качества — по ним агента будем проверять)
Где обязательно решает человек? (что нельзя отдавать ИИ без подтверждения)
 Примеры задач (чтобы поймать идею):
Ассистент-ресёрчер: даёшь тему → собирает свежие данные → отдаёт саммари с источниками.
Поддержка: сообщение клиента → черновик ответа по базе знаний компании.
Контент: новость → 3 поста в твоём стиле (как в проекте-примере «Рой агентов»).
Разбор документов: PDF/договор → ключевые пункты, риски, краткий пересказ.
Личный аналитик: выгрузка из таблицы → выводы и графики на словах.

ЭТАП 2 — Стратегия ​
 Цель: решить, как устроена автоматизация, до написания кода.
 Ключевые развилки
Один агент или несколько («рой»)?
Один — если задача линейная (вход → обработка → выход).
Несколько — если есть разные роли (один ищет, второй пишет, третий проверяет).
 Совет новичку: начни с одного. Расширишь позже (Этап 7).
Человек в контуре. Где агент только готовит черновик, а публикуешь/отправляешь ты сам? На старте — почти везде. Это безопасно и строит доверие.
Что автоматизируем, а что оставляем руками. Не пытайся закрыть 100% сразу. Автоматизируй самый болезненный кусок.
Как понять, что работает. Сформулируй 3–5 проверочных примеров: «на таком входе жду примерно такой выход». Пригодятся для тестов.
 Промт «Предложи стратегию»
Вот моя задача (см. ЗАДАЧА.md). Я новичок. Предложи 2–3 варианта стратегии
автоматизации — от самого простого к более продвинутому. Для каждого объясни
простыми словами: сколько агентов, что делает человек, что автоматизируется,
плюсы и минусы, сколько примерно усилий. Порекомендуй, с чего начать мне, и почему.
Не пиши код — только стратегия.
​
 Проверка
Ты выбрал стартовый вариант (скорее всего — один агент + ты подтверждаешь результат) и понимаешь, почему именно он.

ЭТАП 5 — Первый агент (MVP) ​
 Цель: один агент реально делает кусочек твоей задачи. Это момент, когда «магия» оживает.
 Что сделать
Один агент: дать ему характер (системный промпт — кто он, как себя ведёт) и связать с Claude через SDK.
Самый простой режим: ты пишешь запрос → агент отвечает.
Проверить на твоих примерах из Этапа 2.
 Характер агента — это его системный промпт. Опиши: кто он, что умеет, каким тоном отвечает, чего НЕ делает (не выдумывает факты и т.п.). Хороший промпт = 80% качества агента.
 Промт «Сделай первого агента»
Сделай первого работающего агента для моей задачи (см. ЗАДАЧА.md).

1. Заведи агента с понятным характером (системным промптом): кто он, что делает,
   каким тоном общается, чего не должен делать. Помоги мне сформулировать этот
   промпт под мою задачу.
2. Подключи его к Claude через Claude Agent SDK, доступ — через мой токен из .env.
3. Сделай простой способ с ним работать (пока хватит чата в терминале или простой
   страницы): я пишу запрос — он отвечает.
4. Прогони на 2–3 моих примерах и покажи результат.

Объясни простыми словами, что получилось и где «живёт» характер агента, чтобы я
мог его править.
​
 Проверка
Ты даёшь агенту реальный запрос из своей задачи — и он выдаёт осмысленный результат.  Это уже работающий ИИ-агент.
ЭТАП 6 — Инструменты, или «руки» агента ​
 Цель: дать агенту умения, которых у обычного чата нет: искать свежую информацию в интернете, читать твои файлы, ходить во внешние сервисы.
 Что сделать
Добавить агенту инструменты (tools) — функции, которые он может вызывать сам. Например: «найти свежие новости», «прочитать файл», «отправить сообщение».
Каждый инструмент описывается строго (через zod) и подключается к агенту.
Дать ровно те «руки», что нужны под задачу — не всё подряд.
 Примеры «рук»: веб-поиск свежих новостей, чтение PDF/таблиц, запрос к API (погода, курсы, CRM), отправка в Telegram/почту, сохранение результата в базу.
 Промт «Дай агенту инструменты»
Моему агенту для задачи не хватает «рук». Ему нужно уметь: <перечисли: например
«искать свежие новости по теме», «читать загруженный PDF», «отправлять готовый
текст мне в Telegram»>.

1. Объясни простыми словами, какие инструменты нужны и как они работают.
2. Если для какого-то инструмента нужен платный ключ или доступ — СНАЧАЛА скажи
   мне об этом и предложи бесплатные/простые варианты, где можно.
3. Реализуй инструменты (через zod) и подключи их агенту.
4. Покажи на реальном примере, как агент сам вызывает инструмент и использует
   результат.
​
 Проверка
Агент сам пользуется инструментом (например, реально нашёл свежую информацию) и применяет её в ответе.
ЭТАП 7 — Несколько агентов и оркестрация ​
Делай этот этап, только если одной роли мало. Многим задачам хватает одного хорошего агента.
 Цель: собрать «рой» — несколько агентов с разными ролями, которыми управляет агент-«оркестратор».
 Что сделать
Завести агентов-исполнителей с разными ролями (например: «ищет», «пишет», «оформляет»).
Добавить оркестратора (часто его зовут «Стратег»): он получает цель, разбивает на задачи, раздаёт исполнителям, собирает результат.
Добавить очередь задач, чтобы тяжёлая работа шла в фоне и интерфейс не зависал.
(Очень полезно) добавить агента-Критика, который проверяет результаты на ошибки и «выдумки» до того, как ты их увидишь.
 Промт «Свяжи агентов в рой»
Хочу превратить одного агента в команду («рой»). По моей задаче нужны роли:
<перечисли роли: например «исследователь», «автор», «оформитель»>.

1. Заведи этих агентов с разными характерами (системными промптами).
2. Добавь агента-оркестратора: он получает мою цель, разбивает её на задачи,

3. Сделай фоновую очередь, чтобы работа шла в фоне и ничего не зависало.
4. Добавь агента-Критика: он проверяет результаты на ошибки и выдумки; если плохо —
   задача идёт на доработку, если хорошо — мне на проверку.
5. Покажи весь путь на одном примере: цель → план → исполнение → проверка → результат.

Объясни простыми словами, как это работает и где менять роли агентов.
​
 Проверка
Ты ставишь одну цель — и несколько агентов сообща доводят её до результата, а Критик отсекает явные ошибки.

ЭТАП 9 — Качество, контроль и безопасность ​
 Цель: чтобы агенты не врали, не тратили лишнего и не делали опасного без тебя.
 Что добавить
Проверка на ошибки/выдумки (Критик или фактчек через интернет).
Человек подтверждает всё, что уходит наружу (публикация, отправка клиенту, оплата).
Контроль расходов: видеть стоимость запросов, задать лимит на задачу.
Тесты: прогнать твои проверочные примеры из Этапа 2 и убедиться, что качество держится.
Секреты — только в .env, не в коде и не в git.
 Промт «Добавь контроль качества»
Добавь в систему контроль качества и безопасности:
1. Проверку результатов на ошибки и выдумки перед тем, как я их увижу.
2. Обязательное подтверждение человеком для действий «наружу» (публикация, отправка).
3. Учёт стоимости запросов и возможность задать лимит бюджета на задачу.
4. Набор из <3-5> проверочных примеров по моей задаче и простой способ их прогнать.
5. Проверь, что все секреты лежат только в .env и не попадают в git.

 Мини-словарь (для не-технарей)
Терминал — чёрное окно, куда вводят команды (в VS Code: Terminal → New Terminal).
Репозиторий / git — история версий проекта; можно откатиться назад.
Бэкенд — часть на сервере, где работает логика и агенты.
База данных — хранилище: история, задачи, настройки.
Системный промпт — «характер» агента: кто он и как себя ведёт.
Инструмент / tool / «руки» — действие, которое агент может выполнить сам (поиск, чтение файла, вызов сервиса).
Оркестратор — главный агент, который раздаёт задачи остальным.
MVP — самая простая работающая версия, чтобы проверить идею.
.env — файл с секретами (ключи, токены), который держится в тайне.
API-ключ / токен — «пропуск» к внешнему сервису.
