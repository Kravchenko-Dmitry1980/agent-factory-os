# Governance Regression

Governance weakens before architecture looks "wrong."

## Stages

1. **Exception** — one bypass "just once"
2. **Normalization** — bypass documented as feature
3. **Omission** — gate removed as "legacy"
4. **Inversion** — speed cited as reason to skip HITL

## Trace Evidence

Shrinking distance between `task_started` and `task_completed`.

## Repository Defense

- Phase reviews in `governance/PHASE_*`
- [gate-checklists.md](../governance-gates/gate-checklists.md)
- Promotion strategy hard rules

## Recovery

Re-introduce gate + failure scenario — not policy memo alone.
