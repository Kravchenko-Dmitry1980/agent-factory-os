# Resilient Governance

Governance survives team pressure and time.

## Properties

- Gates documented outside code (doctrine + evolution)
- Fail-closed defaults hard to bypass accidentally
- Promotion pipeline independent of demo hacks
- Phase reviews (governance/PHASE_*)
- Drift signals reviewed on change

## Weak Governance

Rules only in chat / tribal knowledge / "we know not to".

## Strengthen

- Update [gate-checklists.md](../governance-gates/gate-checklists.md)
- Add example to [examples/](../examples/)
- Cross-link observability events

## Metric

Months later, can a new engineer still find why HITL exists?

Must be yes.
