# Small Steps Method

## Principle

One gate, one demo, one exercise at a time.

## Step size guide

| Good step | Too big |
|-----------|---------|
| Run one scenario | Run all demos day 1 without debrief |
| Read one trace | Read entire Books/swarm-playbooks |
| One change proposal exercise | Refactor shared runtime |
| One lesson + checkpoint | Module 00–13 in one weekend |

## Checkpoint before next step

Student answers checkpoint questions in module without looking at answers.

## Why

Cognitive load hides governance. Small steps make missing gates visible.

## For teachers

If student lost → shrink step, not add slides.
